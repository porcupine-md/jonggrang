# UI guide sections

Every `.jonggrang/UI.md` uses these headings:

1. Product and UX rationale
2. Visual direction and baseline
3. Source map
4. Token contract, typography, and spacing
5. Components and layout patterns
6. Interaction, responsive, and accessibility rules
7. References and verification
8. Rules summary

Keep the guide specific to the product. Name real source paths and representative
screens. Include a concrete example for every component or layout pattern an
agent is expected to reuse. State `none` when an optional resource does not
exist; do not invent Storybook, Figma, screenshots, or browser tests.
